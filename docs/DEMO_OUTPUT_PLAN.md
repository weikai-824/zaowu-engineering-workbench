# 造物工程台演示产出规划

> 状态：待评审。当前只定义展示范围、叙事结构和验收门槛，不进入录制、截图、GIF 合成或拍摄脚本实现。

## 1. 产出目标

这轮演示不做功能菜单巡游，而是证明一条可信的工程主张：

`局部设计意图 → Agent 受控规划 → 人工门禁 → 真实工程工具 → 确定性验证 → 新版本与可追溯交付`

Agent 是主叙事，其他动图只补充证明三件事：Agent 操作的是可区分的工程资产、背后有真实私有工艺数据、最终结果经过人工复审并形成工程交付。

| --- | --- | --- | --- | --- | --- |

## 3. Agent 两条动图的分工

### 01：业务闭环主片

主片只回答“用户提出一个局部返工要求后，系统是否真的、安全地把它变成新工程版本”。逻辑范围包括：

- 三维圈选、目标零件、文字要求和当前 Revision 共同构成输入；
- Planner 输出结构化计划，必要时要求澄清；
- 人工批准是副作用边界，拒绝或修改计划不应产生 CAD Job 或新 Revision；
- Executor 只调用 Tool Gateway 白名单，并显式呈现本机 CAD 等待；
- Verifier 核对新版本、CAD hash、资产来源、锁定接口、数字检查和执行签名；
- 成功态回到用户结果：新 Revision、新 CAD 资产、三维模型重新载入；同时保留“物理验证未执行”的真实边界。

### 02：工程机制解释片

辅片回答“为什么这不是一次性的 AI 魔术”。逻辑范围包括：

- `选择与意图 → 规划 → 人工确认 → 执行修改 → 工程验证 → 新版本` 六阶段状态；
- 阶段状态由事件和 checkpoint 重建，不使用演示占位状态；
- 工具调用顺序、结果、执行/验证耗时和幂等关联可检查；
- 人工等待、本机 CAD 等待、失败、重试和重规划被单独记录；
- 页面刷新或服务恢复后继续同一个 Run，不重复制造副作用。

## 4. 不单独制作的内容

- 不单独录“实时 Tripo 生成”：网络、额度和耗时波动大，且会把重点从工程 Agent 拉回普通生成式 AI。
- 不单独录“CAD 执行器跑任务”：它已经是 Agent 主片的真实工具层；重复一条只会稀释叙事。
- 不把连接设置做成长动图：连接矩阵更适合一张静态证据图或现场讲解时短暂停留。
- 不展示 Studio Graph Mode 为现有能力；当前可展示的是产品内六阶段图和 LangSmith trace 能力。
- 不宣称任意 STL/OBJ/GLB 局部雕刻已经自动化；首条闭环限定为受控参数化 CAD 返工。
- 不使用“生产就绪、实体已验证、可直接量产”等超出现有证据的表述。

## 5. 产物组织约定

正式执行时统一写入一个新的当前批次目录，避免重新混入测试截图：

```text
artifacts/demo-current/
  README.md
  01-agent-closed-loop/
    master.mp4
    share.gif
    poster.png
    manifest.json
  02-agent-governance-recovery/
  03-reference-vs-cad/
  04-engineering-output/
  05-private-process-library/
  06-offline-slicing-evidence/   # 条件项
```

- `master.mp4`：高质量母版，用于现场演示和后续重新转码。
- `share.gif`：README、聊天或文档内直接播放的轻量版。
- `poster.png`：动图首帧/封面，不再额外拍一套重复截图。
- `manifest.json`：记录 commit、项目 Revision、Run ID、分辨率、帧率、产出时间和真实性边界。
- 原始帧、浏览器 profile 和临时下载只放 `work/demo-capture/`，验收后删除，不进入正式产物目录。

建议母版保持统一的 16:9 视口；GIF 使用统一宽度、10–12 fps，并以清晰可读为先，不用高帧率换取巨大文件。

## 6. 内容与真实性标准

每条动图必须满足：

1. 只证明一个主要结论，和其他动图没有大段重复。
2. 使用真实 UI、真实业务状态和真实返回数据，不注入假的成功态或演示计时器。
3. 开始状态、关键门禁和最终证据都可读；等待过程可以压缩，但不能改写执行顺序。
4. 不暴露密钥、服务 token、本机路径、用户标识或无关账户信息。
5. Agent 片保留 Run/Revision/资产数量等可核对信息；敏感 ID 可做一致性遮罩，不能前后变成不同记录。
6. 画面中的能力边界与代码一致：数字验证不等于物理验证，签名来源不等于独立重算，切片一致性不等于生产放行。
7. 每条产物均能从 manifest 对应回固定演示项目和代码版本。

## 7. 录制前验收门

进入落实阶段前，需要逐项确认：

- 完成一次人工浏览器验收：三维画圈发起 Agent，成功后新几何在原工作台自动重新呈现。
- 建立专用演示项目副本，固定初始 Revision、CAD 参数、锁定接口和工艺绑定；不在主验证项目上反复制造版本。
- Agent Service、PostgreSQL、Tool Gateway、D1/R2 和本机 CAD 执行器通过同一次预检。
- 主场景支持重复执行，且相同 `clientRequestId` 不产生重复 CAD Job、Execution Run 或 Revision。
- 当前拓扑/Worker 检查若仍有浏览器资源加载问题，不把该检查作为正向画面；修复并复验后再纳入。
- 离线切片只有在准备好与当前 Revision 一致的真实结果后才进入首批产出。

## 8. 本轮建议结论

建议批准的首批范围是 **01–05**：两条 Agent、双轨模型、工程输出、私有工艺库。06 离线切片保持条件项。

评审时只需要确认三个选择：

1. Agent 辅片优先突出“刷新/重启恢复”，还是“人工修改要求后重规划”；
2. 首批是否保留 05 私有工艺库，还是压缩为四条；
3. 离线切片是否值得为当前 Revision 重新准备一份真实结果。
